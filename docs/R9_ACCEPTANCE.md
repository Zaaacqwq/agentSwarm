## 和方案不同的地方

1. **被测 App 用苹果的 App Sandbox 运行，不用 `sandbox-exec`。**
   - 审阅时发现，用 `sandbox-exec` 时，被测 App 可以让系统打开一个它写出的脚本，绕过沙箱。
   - 改为 swarmd 换掉 App 的包名，去掉它原有的签名和权限，只加 App Sandbox 权限后重新签名，再由系统启动。
2. **试过以工作站用户（`ws-N`）的身份运行，没有成功，已撤回。**
   - 目的是让被测 App 连你的钥匙串都读不到。
   - 但 App Sandbox 要找"当前用户"的系统服务初始化；一个 `ws-1` 的进程跑在你的桌面会话里，那个服务不接受它，App 在启动时就崩溃了。
   - 去掉沙箱改以 `ws-N` 运行，反而更危险：它能请求系统以你的身份打开别的程序。
   - 你选择回到"以你的身份、在 App Sandbox 里运行"，并加上剪贴板保护。`ws-app` 和那条 sudo 规则已删除；下次运行 `--update-exec` 时会把它们从系统里清掉。
3. **会话期间剪贴板是空的**（方案里没有）。会话开始时，助手把你剪贴板里的内容存起来再清空，结束后恢复；如果你中途复制了新内容，就不会被旧内容覆盖。
4. **助手用你的 Apple Development 证书签名**，所以重新编译后，"辅助功能"和"屏幕录制"不用重新授权。安装脚本是 `zsh scripts/setup-desktop.sh`，不用 sudo。

## 实测（R9.0，2026-10-19，你在电脑前）

一个专门的探测 App 在 App Sandbox 里尝试越界，结果如下：

| 尝试 | 结果 |
|---|---|
| 读 `~/Documents`、`~/Desktop`、`~/.ssh`、shell 历史、`~/.config`、邮件、信息，以及 agentSwarm 自己的目录 | 被拦 |
| 列出 `~/Library/Keychains`、读登录钥匙串文件 | **能读到**（见"剩余问题"） |
| 往家目录、往 `/tmp` 写文件 | 被拦 |
| 联网 | 被拦（连域名都解析不了） |
| 用 `/bin/sh` 往沙箱外写文件 | 被拦 |
| 让"终端"运行它写出的 `.command` 脚本 | 被系统拒绝，提示"已损坏"（文件带了隔离标记） |
| 用 AppleScript 控制访达 | 被拦 |
| 连助手的 socket | 被拦 |
| 读剪贴板（会话中） | 读到的是空的；会话结束后原内容恢复 |

助手这一侧：
- 截图只截到被测 App 的窗口；
- 点到窗口外、按 cmd+tab 都被拒绝；
- 你动鼠标或键盘时，Agent 的操作会暂停；Agent 自己的点击不会被当成你在用电脑；
- 有通知横幅盖在 App 上时，那次点击被拒绝（识别为"通知中心"）。

另外在 `ws-1` 上真实编译了一次 Notes App（13 秒），打包、暂存、签名都正常。

## AGE-1 的过程

- **用时和花费**：69 分钟（到验证阶段为止），$1.09，7 个 Agent：lead、2 个调研员、2 个 QA、2 个审查员。
- **你出手的次数**：回答问题、批准方案、两次批准桌面、回复一次让 lead 继续，最后还要合并 PR。
- **桌面会话**：
  - QA 打开 App 时，几次因为你在用这台 Mac 而暂停，你离开后就继续了。
  - 有几次点击被拒绝，有时是通知横幅挡住了，有时是系统替 App 绘制按钮、输入框的服务进程被误判成了"别的 App"。后一种已修复，见下文。
- **结论**：流程本身能走通，但对一个 6 行的改动来说太重了：调研、讨论、两次 QA、给 QA 报告配的审查员，还有 lead 自己去分析截图的像素。这直接促成了 R10"简化工作流"（`docs/R10_IMPLEMENTATION_PLAN.md`）。

## 审查后的改动

**安全审查：** 1 个严重问题、4 个高级别问题，都已修复。
- **严重**：被测 App 的主程序如果是一个脚本，系统运行的其实是 `/bin/sh`，它不受 App Sandbox 限制。
  - 修复：只接受编译出来的 Mach-O 程序；App 打开后，助手再确认它确实在沙箱里，不在就立刻关掉。
- **解压**：改用 tar，解压前核对清单，只能有这一个 App，不能有 `..`，大小有上限；App 自身不能是一个链接；包里的链接不能指向 App 外面。
- **点击**：每次点击前，用辅助功能确认点到的确实是被测 App，透明窗口之类的穿透点击会被识别出来。
- **输入**：每输一小段之前，都重新确认会话还在、你没在用电脑、焦点还在被测 App 上。
- **快捷键**：改成白名单，只放行编辑键和 App 自己的 Command 快捷键。
- **App 包内容**：删掉登录项、XPC 服务、插件，以及 Info.plist 里注册 URL scheme、文档类型、修改启动环境的配置；包里还套着别的 App 就拒绝。

**代码审查：** 3 个高级别问题，都已修复。
- 批准、拒绝、结束同时发生时的竞争。
- 任何时候都不给已经结束的运行发消息，否则会让它重新开工。
- 助手卡在截图时，停止命令也会被一起堵住。

**验收中发现并修复的：**
- 内存压力处在"警告"时，桌面测试也被挡着不开工。现在内存压力只拦模拟器和浏览器。
- 打开 App 时遇到你在用电脑，会直接失败，Agent 只能反复重新编译再试。现在会原地等你停手。
- 桌面申请的说明超过 300 字会被整条退回。现在自动截断。
- 系统替 App 绘制按钮和输入框的服务进程被当成了"别的 App"。现在只放行几个专门画控件的系统服务，打开和保存文件的对话框仍然拒绝：在那里选文件等于给沙箱里的 App 开权限。

## 剩余问题

- **钥匙串文件读得到。** 这是苹果沙箱为了兼容旧接口留的口子。
  - 文件用你的登录密码加密，被测 App 也联不了网。
  - 但它能把文件内容显示在窗口上，Agent 截图后就会传给模型服务商；拿到文件的人可以离线去猜你的登录密码。
  - 要走到这一步，Agent 得先被恶意内容操纵，并故意写出这样的代码。你的登录密码够强，风险就小。
  - 彻底的办法是在 macOS 虚拟机里跑被测 App，已记在 PLAN.md 第 17 节，等 Mac Studio 到位。
- **剪贴板**：会话期间是空的；但如果你在会话中途复制了东西，被测 App 能读到。
- **通知横幅**：横幅出现的那一刻，盖住的点击会被拒绝，Agent 要重试。安全上没问题，只是多花几步。
- **证据截图带坐标网格**：Agent 看的截图带网格，存进 PR 的也带。不影响阅读，以后可以把存档用的那份去掉网格。
- **工作流太重**：由 R10 处理。
