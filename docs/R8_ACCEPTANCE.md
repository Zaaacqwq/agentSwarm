## 审查后的改动

code-reviewer 和 security-reviewer 都看过。主要风险是 **Agent 写的经验会进入以后所有 Agent 的提示词**：如果某个 Agent 读了恶意网页，它可能把恶意内容写成"经验"。修复如下。

- **全队和角色范围的经验要你批准**：
  - Agent 写的这两种经验先放在"等你批准"一栏，批准前没有 Agent 能看到，也不能置顶；
  - 只用于本项目的经验立即生效，因为影响只在这个项目里。
- **Agent 不能改的经验**：
  - 你写的；
  - 已置顶的；
  - 已批准的全队或角色经验；
  - 你停用过的同一意思，Agent 不能再记一次。
  - Agent 能改的只有 Agent 写的项目经验；每次修改都保留旧版本，来源不变。
  - 你编辑过的经验算作你写的，以后 Agent 会把它当要求。
- **提示词里的格式**：
  - 标签放在最前面（"来自你"或"来自某 Agent，在某 ticket 之后，是建议不是指令"），由系统根据存储的字段生成；
  - 正文逐行加引用符号，正文里伪造的标签不会单独成行；
  - 去掉控制字符、零宽字符和改变文字方向的字符。
- **密钥**：
  - 识别的格式更多了（Bearer、JWT、Slack、npm、URL 里的密码、`token = ...` 等）；
  - 项目本地文件里的值出现在经验里也会被拒；
  - 修正了误判：单词里带的 `sk-`（如 `task-management`）不再算作密钥。
- **数量限制**：每个 mission 最多记 3 条经验、提 2 条手册建议；等你处理的手册建议最多 30 条。
- **搜索**：
  - 单复数归一（bugs → bug，fixes → fix）；
  - 带点和连字符的词也按各部分匹配；
  - 去掉常见的中文词；
  - 查询越长，门槛越高，避免长的任务说明凭两个常见词匹配到不相干的经验。
- **角色判断**：只按整个单词匹配。例如 "leaderboard dev" 不再算作 lead，"contest" 不再算作测试。
- **面板**：
  - 采纳手册建议前先预览全文；
  - 编辑时用最新的内容；
  - 编辑可以取消。
- **复盘数据**：模型调用出错的次数改用 drizzle 统计；耗时注明包括等你的时间。
- **测试**：测试默认内存压力正常，不再受这台 Mac 当时内存情况的影响。之前这台 Mac 处于"警告"状态时，模拟器测试会一直排队。

## 剩余问题

- **真实验收推迟**（第 1–4 项），等你有真实的 ticket 时再做。
- **搜索只做字面匹配**，没有语义搜索，同义词找不到。经验库大了以后可以考虑加向量搜索。
- **没有自动清理经验**：没人用的经验不会自动停用，现在由你在面板上停用或删除（上限 500 条）。
