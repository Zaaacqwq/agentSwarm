## 实测中发现并解决的问题

1. **Swift 宏编不过。** 编译器运行宏插件时、SwiftPM 解析清单和运行包插件时，都会再套一层自己的沙箱，而沙箱里套不了沙箱。
   - 修法：`xcodebuild`、`swift`、`swiftc` 包装脚本放在 Agent 的 PATH 最前面，关掉内层沙箱（`-disable-sandbox` 和 xcodebuild 的三个选项）。
   - 外面两道墙（独立用户和 seatbelt）不变。
2. **工作站上 xcodebuild 和 simctl 截图报 Operation not permitted。**
   - 原因：Foundation 在外接卷上保存文件，要经过 `<卷>/.TemporaryItems/folders.<uid>`。
   - 修法：seatbelt 只放行这个用户自己的那个目录。
3. **simctl 截图在沙箱里仍然失败**，改用 AXe 截图。
4. **xcodebuild 不指定 DerivedData 时写到 `/Users/ws-N`**，被沙箱挡住。包装脚本改为默认写到本次运行自己的家目录。
5. **局部放大裁错位置。** sips 把偏移量 0 当成"没给"，从中心裁。改为至少从 1 开始；测试按像素颜色检查裁剪位置，去掉修复时这个测试会失败。
6. **刚抹掉的设备第一次启动 App 要几秒才画出界面**，太早截图是白屏（R0 也遇到过）。点击后工具会等 1.5 秒；QA 的工作说明里写明先读界面再截图。
7. **浏览器在缺失的目录里启动失败时，返回的原因是空的。** 已改为说明原因。

### 防火墙（审查后增加）

- **为什么加：** 安全审查指出，seatbelt 只能按端口拦。工作站能经 tailnet 地址的 443 端口访问你挂在 `tailscale serve` 上的服务，从而绕过端口禁止名单；浏览器的地址检查也挡不住 DNS 重绑定。实测确认了：加规则之前，ws-8 能连上这两处。
- **怎么做的：** 安装脚本加了一组 pf 规则（锚点 `com.apple/agentswarm`），只匹配 ws-1…ws-8 的用户编号。它们连接局域网、tailnet、链路本地和组播地址（IPv4 和 IPv6）时，立即被拒绝。开机时由 LaunchDaemon `com.agentswarm.pf` 重新载入。安装脚本装完会自动验证。
- **怎么撤销：** 运行 `sudo pfctl -a com.apple/agentswarm -F all`，再删掉那个 LaunchDaemon 的 plist。
