## 真实模型验收

- 脚本：`evals/runner/p3-acceptance.ts`。模型 `qwen/qwen3.8-omni-flash`，thinking 设为 `low`。
- 两个 dev Agent 分别绑定 `ws-1` 和 `ws-2`。
- **A：群里分派、并行修复**
  - 一条群消息同时 @ 两个 dev Agent，分别修复 `hive-sandbox` 里的 chunk 和 backoff；
  - 两人各自 checkout、修改、跑测试、经 Git Relay 推送并开 PR，然后在群里回复 PR 链接；
  - 第三个 Agent Cleo 只有沟通权限，在两人工作期间回答了私聊。
- **B：讨论 backoff 是否加 jitter**
  - Ana 先给出观点并 @ Ben，Ben 回复后，Ana 写结论；
  - 结论是：保持 `backoffDelay` 是确定性的，另外提供可选的 `backoffDelayWithJitter` 包装函数。
- **C：无限计数游戏**
  - 让 Ping 和 Pong 用 `message_agent` 无限计数；
  - 会话链预算（8 条）用完后暂停，并在 Agent 间会话里发出系统消息。
- **花费**：总共 $0.0201，输入 90,676 tokens，输出 9,219 tokens。
- 验收产生的 PR #26、#27 已关闭，分支已删除。

## 开发中发现并修复的问题

- **drizzle 生成的迁移会删光消息。** 它在 SQLite 里重建 `channels` 表时，会级联删除所有消息和成员，而它写的 `PRAGMA foreign_keys=OFF` 在迁移事务里不生效。现在改为在事务外关闭外键，迁移完成后做外键检查，并有测试验证旧数据保留。
- **删除 Agent 会连带删掉它所在的群和所有人的历史。** 现在只删它的私聊，群里只移除它的成员资格，群历史保留（作者名是快照）。
- **WebSocket 事件按组织整体广播（P1 起就是这样）。** 现在消息、反应、频道事件只推送给能读该频道的人。
- **代码审查发现的其他问题：**
  - 停止回合后，等待中的写租约不会被拿到、也不会滞留；
  - 第一条 `message_agent` 被拒绝时，不再留下空的 Agent 间会话；
  - 每个回合的分支会话链在回合结束后释放；
  - 防抖延迟有上限，不会被持续的消息无限推迟；
  - 等太久被丢弃的 Agent 回合会发系统消息说明；
  - `around` 分页正确遵守 limit；
  - 搜索跳转打开的窗口与实时最新页分开缓存。
