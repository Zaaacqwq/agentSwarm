# R9 实施方案（草稿）：桌面会话

> 依据：
> - `PLAN.md` 第 9 节（Mac 原生 App）、第 14 节、第 15 节第 1 条（允许移植旧 PR 里验证过的小模块）；
> - 旧 PR #5（Hive P5）的 Swift 桌面助手 Hive Desktop 和它的验收记录；
> - R6 的模拟器和浏览器（重任务槽、QA 截图留痕）。
>
> 第 11 节的问题等你决定。

## 0. 本阶段解决什么

Agent 现在能编 iOS App、在模拟器里点，也能在无头浏览器里测网页，但碰不了 Mac 原生 App。R9 让 QA 能在这台 Mac 的桌面上打开 Agent 编出来的 Mac App，看界面、点击、输入、截图，写出带截图的验收报告。

难点有两个，都和"桌面是你的"有关：
- **桌面只有一个，而且你在用。** 这台 Mac 登录的是你的账号，接着两块屏幕。Agent 操作时会和你抢鼠标；它截的图会发给模型提供方，可能截到你的私人内容。
- **Agent 编的 App 要在你的账号下运行。** 工作站用户 `ws-N` 没有图形会话，Mac App 只能在你的会话里打开。不加限制的话，这段 Agent 写的代码能读你的家目录、联网，等于绕过了沙箱。

所以本阶段的重点是边界：
- 每次会话都要你批准；
- Agent 只看得到、点得到被测的那个 App；
- 被测 App 在沙箱里运行；
- 你一动鼠标或键盘，Agent 就停下。

## 1. 验收（真实环境）

1. **一张 Mac App 的 ticket 走完全程**：
   - lead 派开发者改代码，在沙箱里用 `xcodebuild` 编出 `.app`；
   - QA 申请桌面会话，你在手机上批准；
   - QA 打开 App，按验收标准逐条点完，每条附截图；
   - 验收报告和 PR 里带这些截图。
2. **边界有效**：
   - 会话里截图只有被测 App 的窗口，看不到其他窗口；
   - Agent 点击或输入到被测 App 以外的地方会被拒绝；
   - 被测 App 读不到你的家目录，也连不上网（除非项目档案里允许）。
3. **随时能停**：
   - 你在面板、Discord 或菜单栏点"停止"，Agent 马上失去控制；
   - 你动一下鼠标，Agent 暂停，并在 ticket 里说明原因；
   - 会话到时间自动结束，被测 App 被关掉。

## 2. 先做实测（R9.0）

有三件事必须先在这台 Mac 上试过才能定方案。实测会在你的屏幕上弹出窗口，所以等你说可以了再做，大约 15 分钟：

1. **沙箱里能不能打开 Mac App。** 在你的会话里用 `sandbox-exec` 直接启动 App 的可执行文件，配置为禁止读家目录、禁止联网，看 App 能否正常显示和响应点击。
   - 不行的话，试第 2 种：用 `launchctl asuser` 以 `ws-N` 的身份在你的图形会话里启动 App。
   - 两种都不行，就只能不加沙箱运行。这时第 11 节第 2 条需要你重新决定。
2. **只截一个 App 的窗口。** 用 ScreenCaptureKit 按窗口截图，确认截不到其他 App，也不受两块屏幕的影响。
3. **识别"你在操作"。** 区分你本人的键鼠事件和助手发出的事件。
   - 用事件来源区分：助手用自己的事件源，你的输入来自硬件。
   - 确认 Agent 点击时不会误判成你在操作。

## 3. 桌面助手（移植 Hive Desktop）

旧 PR #5 的 Hive Desktop 大约 850 行 Swift，已经在这台 Mac 上验证过：截图、点击、键盘输入、读辅助功能树、会话、停止锁存、禁区。R9 审阅后移植过来，改名为 **agentSwarm Desktop**。

- **运行方式**：
  - 以你的账号作为 LaunchAgent 运行，菜单栏有图标和"停止"项；
  - 通过 `~/Library/Application Support/agentSwarm/desktop.sock` 和 swarmd 通信，只有你的账号能访问；
  - 每个请求带会话令牌，令牌由 swarmd 在你批准时发给助手，会话结束即失效。
- **签名**：用一个固定的自签名证书签名。
  - P5 的教训：临时签名时，系统按程序哈希认它，每次重新编译后都要你在"辅助功能"和"屏幕录制"里删掉再重新授权。
  - 固定证书签名后只需授权一次。
- **安装**：`scripts/setup.sh --desktop` 负责编译、签名、装 LaunchAgent。
  - 授权只能你本人来做：在"系统设置 → 隐私与安全性"里给它开"辅助功能"和"屏幕录制"。
  - 安装脚本会打开对应的设置页面。
- **保留 P5 的做法**：
  - 停止锁存：按过停止后，必须由 swarmd 撤销所有会话、确认之后才能再启用；
  - 禁区作为兜底：系统设置、钥匙串、终端、密码管理器、脚本工具、启动器、agentSwarm 面板；
  - 危险快捷键被拦截。
- **新增**：
  - 白名单（第 5 节）；
  - 按窗口截图；
  - 检测你的操作；
  - 激活指定 App；
  - 在沙箱里启动被测 App（第 6 节）。

## 4. 桌面会话

- **申请**：QA（或带 `needs: ["desktop"]` 的开发者）调用 `desktop_request`，说明要打开哪个 App、做什么、需要几分钟（默认 15，最长 30）。
- **批准**：
  - 只有你能批准。在 ticket 页面上批准，或者点 Discord 消息里的按钮；手机上也能操作。
  - 批准时显示 App 名称、Agent 的说明和时长。
  - 你没回应时，Agent 等待，不占名额。
- **同一时间只有一个会话**：
  - 桌面是一个独占的重任务槽，和模拟器、浏览器的槽分开；
  - 其他申请排队，按 ticket 的优先级。
- **结束**：
  - 有四种情况：Agent 调用 `desktop_release`、到时间、你点停止、运行结束；
  - 结束时关掉被测 App，撤销令牌，助手回到未启用状态。
- **你在操作时**：
  - 会话期间助手一旦发现你的键鼠操作，就暂停 Agent 的点击和输入，Agent 收到"你正在使用这台 Mac"；
  - 你停止操作 30 秒后自动恢复；
  - 你也可以直接点停止。

## 5. 只看得到、只点得到被测的 App

P5 用的是禁区（黑名单）：除了禁区里的 App，Agent 都能看到、都能操作。R9 改成白名单：
- 会话只属于一个 App，也就是被测的那个；它弹出的窗口和对话框也算在内，按进程判断。
- **截图**：只截这个 App 的窗口，其他 App 和桌面都截不到，你的私人内容不会发给模型提供方。
- **点击和输入**：
  - 坐标必须落在这个 App 的窗口上；
  - 输入只在它是最前面的 App 时才允许；
  - 不满足条件时拒绝，并告诉 Agent 原因。
- **切换**：`desktop_focus` 只能把这个 App 切到最前面，不能切到其他 App。P5 验收时 Agent 卡在 iTerm2 前面就是因为没有这个工具。
- **先看后动**（借鉴 agent-swarm-ng）：
  - 每次看一眼（截图或读界面结构）之后，最多连续 3 次点击或输入，然后必须再看一眼；
  - 防止 Agent 不看屏幕连续乱点。

## 6. 被测 App 怎么运行

- **从哪来**：开发者在 `ws-N` 的沙箱里编出 `.app`（在 worktree 的构建目录里），QA 用 `desktop_open` 指定路径。
  - swarmd 通过 ws-exec 把它打包取回，放进只有你的账号能访问的暂存目录：`~/Library/Application Support/agentSwarm/apps/<run>/`；
  - 只接受这次运行自己编出来的 App，不接受系统里已装的 App。
- **怎么运行**（取决于第 2 节的实测）：
  - **推荐：在沙箱里运行。** 禁止读写你的家目录，只能写自己的临时目录；默认禁止联网，项目档案里可以允许 localhost 或指定域名。
  - **备选：以 `ws-N` 的身份运行。** 前提是实测可行。
- **结束时**：关掉 App，删除暂存目录。

## 7. Agent 的工具

| 工具 | 作用 |
|---|---|
| `desktop_request` | 申请会话：要测的 App、做什么、时长。这次执行结束，你批准后带着会话继续 |
| `desktop_open` | 打开这次运行编出的 `.app`（在沙箱里） |
| `desktop_look` | 截被测 App 的窗口（可以局部放大），同时返回它的界面结构：按钮、文本框及编号 |
| `desktop_click` | 按界面结构里的编号点击，或者按截图坐标点击 |
| `desktop_type` | 输入文字；`desktop_key` 发送快捷键（危险组合被拦截） |
| `desktop_focus` | 把被测 App 切到最前面 |
| `desktop_release` | 结束会话 |

截图按 R6 的方式处理：
- 存进 ticket 的截图记录；
- 上下文里只保留最新几张；
- QA 的验收报告可以引用。

## 8. 面板和 Discord

- **ticket 页面**：
  - 待批准的桌面申请显示为醒目的卡片，带"批准"和"拒绝"；
  - 会话进行中显示实时截图（只有被测 App）、剩余时间和"停止"。
- **Discord**：申请时发消息，带批准和拒绝按钮；会话开始、结束、暂停也发通知。
- **设置 → 这台 Mac**：
  - 显示助手的状态：没装、缺哪项授权、正常、被停止锁住；
  - 给出安装和授权的步骤。
- **菜单栏**：会话进行中图标变色；"停止"一键结束。

## 10. 不做的

- 操作系统里已经装好的第三方 App（只测这次编出来的 App）。
- 同时开多个桌面会话。
- 在虚拟机里跑 macOS（隔离最好，但这台 16 GB 的 Mac mini 带不动，留到 Mac Studio 到位后再考虑）。
- 录屏。只有截图。

## 11. 需要你决定的

1. **Agent 能看到和操作的范围：只限被测 App（白名单），还是除禁区以外都可以（P5 的黑名单）？**（推荐白名单）
   - 白名单下截图只有被测 App，你的私人内容不会发给模型提供方；
   - 代价是 Agent 不能借助其他 App，例如用访达选文件。
2. **被测 App 在沙箱里运行，还是不加限制运行？**（推荐沙箱）
   - 不加限制，等于让 Agent 写的代码以你的身份运行。
   - 如果第 2 节的实测证明沙箱和 `ws-N` 两种方式都不行，我会停下来，带着替代方案回来问你。
3. **每次会话都要你批准吗？**（推荐每次都批准）
   - 默认 15 分钟，最长 30 分钟，用手机就能批准。
   - 也可以对某个项目设成"自动批准"，但你不在电脑前时 Agent 就会直接操作你的桌面。
4. **你一动鼠标或键盘，Agent 就暂停吗？**（推荐暂停）
   - 你停止操作 30 秒后，Agent 自动继续。
5. **验收用哪个 Mac App？**（推荐由我做一个小的演示 App）
   - 例如一个 SwiftUI 的记事 App，放在沙盒项目里，专门用来验收。
   - 如果你有自己的 Mac App 想用来验收，告诉我是哪个仓库。
6. **助手用固定的自签名证书签名吗？**（推荐用）
   - 这样只需在系统设置里授权一次。
   - 不用的话，每次更新助手都要你重新授权。
7. **R9.0 实测什么时候做？**（推荐等你在电脑前的时候）实测会在你的屏幕上弹出 App 窗口，大约 15 分钟。
